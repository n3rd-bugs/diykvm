DIY PiKVM — API guide for Claude & other agents

A KVM-over-IP appliance: drive the target's keyboard/mouse, watch its screen, manage a virtual USB drive (an EFI System Partition), and talk to a serial console — all over HTTP/WebSocket. LAN-only.

Machine-readable? GET /api returns this whole endpoint list as JSON (public, no auth) — agents can fetch it to discover everything below programmatically.

1. Authentication

Humans log in at /login (session cookie). Agents use the API key. Get it by exchanging credentials once:

curl -s -X POST http://<pi>:8000/api/login \
     -d username=admin -d password=YOURPASS
# -> {"api_key":"<KEY>"}

Then send the key on every request — HTTP header X-API-Key: <KEY> (or Authorization: Bearer <KEY>); for WebSockets add ?token=<KEY> to the URL.

2. Input — keyboard & mouse WS /ws

Connect to ws://<pi>:8000/ws?token=<KEY> and send JSON messages:

MessageEffect
{"t":"kd","code":"KeyA"}key down (code = JS KeyboardEvent.code)
{"t":"ku","code":"KeyA"}key up
{"t":"mm","x":0.5,"y":0.5}absolute move — x,y normalized 0..1 over the target's primary display
{"t":"mr","dx":10,"dy":-4}relative move (trackpad), signed −127..127
{"t":"mb","button":0,"down":true}button 0=left 1=middle 2=right (JS MouseEvent.button)
{"t":"mw","dy":1}wheel (±1)
{"t":"reset"}release all keys & buttons

Keys: use KeyboardEvent.code values — letters KeyA..KeyZ, digits Digit0..Digit9, Enter Escape Backspace Tab Space, F1..F12, Arrow{Up,Down,Left,Right}, Home End PageUp PageDown Insert Delete, modifiers ControlLeft ShiftLeft AltLeft MetaLeft (and the Right variants), punctuation Minus Equal BracketLeft BracketRight Backslash Semicolon Quote Backquote Comma Period Slash. To type a capital "A": kd ShiftLeft, kd KeyA, ku KeyA, ku ShiftLeft.

Example (Python)

import asyncio, json, websockets
async def type_hello(pi, key):
    async with websockets.connect(f"ws://{pi}:8000/ws?token={key}") as ws:
        for c in ["KeyH","KeyI"]:
            await ws.send(json.dumps({"t":"kd","code":c}))
            await ws.send(json.dumps({"t":"ku","code":c}))
        await ws.send(json.dumps({"t":"mm","x":0.5,"y":0.5}))   # cursor to screen center
asyncio.run(type_hello("192.168.1.120","<KEY>"))

4. Virtual USB drive / EFI boot media /api/msd/*

The target sees a removable USB disk (a GPT disk with a FAT32 EFI System Partition). The drive is either attached to the target or mounted on the Pi for editing — never both.

EndpointDoes
GET /api/msd/status{state, attached, editing, can_edit, image_size}
POST /api/msd/detacheject from target, mount the ESP on the Pi (enables file ops)
POST /api/msd/attachunmount on Pi, hand the disk back to the target
GET /api/msd/ls?path=list a directory (only while editing)
POST /api/msd/upload?path=multipart file=@… upload
GET /api/msd/download?path=download a file
POST /api/msd/mkdir?path= · DELETE /api/msd/rm?path=make / remove
# put a UEFI bootloader on the ESP, then boot the target from it
curl -s -X POST -H "X-API-Key: <KEY>" http://<pi>:8000/api/msd/detach
curl -s -H "X-API-Key: <KEY>" -F file=@BOOTX64.EFI \
     "http://<pi>:8000/api/msd/upload?path=EFI/BOOT"
curl -s -X POST -H "X-API-Key: <KEY>" http://<pi>:8000/api/msd/attach

Boot images — upload a whole image / ISO

Instead of editing the EFI drive, upload a complete disk image or installer ISO and hand it to the target.

EndpointDoes
GET /api/msd/imageslist images: {images:[{name,size,attached,default,cdrom}], attached}
POST /api/msd/images/uploadmultipart file=@disk.img — stream a whole image/ISO into the library (.img/.iso/.bin/.raw)
POST /api/msd/images/attach?name=hand that image to the target (ISOs are exposed read‑only as a CD‑ROM)
POST /api/msd/ejectremove the medium from the target
DELETE /api/msd/images?name=delete an image (not the attached one or the default EFI drive)
# upload an installer ISO and boot the target from it
curl -s -X POST -H "X-API-Key: <KEY>" -F file=@ubuntu.iso \
     http://<pi>:8000/api/msd/images/upload
curl -s -X POST -H "X-API-Key: <KEY>" "http://<pi>:8000/api/msd/images/attach?name=ubuntu.iso"

5. Serial console /api/serial/ports WS /ws/serial

GET /api/serial/portslist serial ports: {ports:[{device,desc,hwid}]}
WS /ws/serial?device=/dev/ttyUSB0&baud=115200&token=<KEY> Binary-clean. Serial RX arrives as WebSocket BINARY frames (raw bytes). To transmit, send BINARY frames (written verbatim) or TEXT frames (UTF-8). Status lines (connected/closed) arrive as TEXT frames — tell them apart from serial data by frame type.
import asyncio, websockets
async def console(pi, key, dev):
    url=f"ws://{pi}:8000/ws/serial?device={dev}&baud=115200&token={key}"
    async with websockets.connect(url) as ws:
        await ws.send(b"\r")                            # bytes -> written verbatim
        async for msg in ws:
            if isinstance(msg, bytes): handle_serial_bytes(msg)   # raw RX (lossless)
            else: print("[status]", msg)               # text frame = status/info
asyncio.run(console("192.168.1.120","<KEY>","/dev/ttyUSB0"))

6. Power, KVM switch & configuration /api/power /api/kvmswitch /api/config

Configure the GPIO targets on the /config page first. Target power — each target's GPIO drives a relay that connects or cuts its power (latched on/off):

EndpointDoes
GET /api/power/state{enabled, available, targets:[{label, on}]} — on is true (powered), false (cut), or null (not yet driven)
POST /api/power {"index":0,"on":true}connect power to that target ("on":false cuts it — a hard power-off)

External KVM switch — pulse a GPIO to press a hardware switch's select button (display + USB):

GET /api/kvmswitch/state{enabled, available, ports:[{label}]}
POST /api/kvmswitch {"index":0}momentary press of the Nth select button (switch to that target)

Both return 409 if disabled or the index isn't configured.

Read or change settings (i.e. /etc/kvm/kvm.conf) programmatically:

GET /api/config{sections:[{section,title,note,fields:[{key,label,type,value}]}]}
POST /api/configbody {"<section>":{"<key>":"<value>"}} — validated server-side (unknown keys / bad values rejected with 400). Power settings apply immediately; web/video/USB changes need the relevant service restart.
POST /api/config/restart-streamerrestart the video streamer to apply [video] changes
# connect power to the first target, then switch the KVM to it
curl -s -X POST -H "X-API-Key: <KEY>" -H "Content-Type: application/json" \
     -d '{"index":0,"on":true}' http://<pi>:8000/api/power
curl -s -X POST -H "X-API-Key: <KEY>" -H "Content-Type: application/json" \
     -d '{"index":0}' http://<pi>:8000/api/kvmswitch

7. Notes

  • The mouse maps to the target's primary display (absolute) — use relative mr for multi-monitor targets.
  • The emulated keyboard is a USB boot keyboard, so it works in the target's BIOS/UEFI setup and boot menus — not just the running OS.
  • GPIO power and KVM-switch control must be wired and enabled on the /config page first; cutting a target's power is a hard power-off (unsaved work is lost).
  • Rotate the API key by re-running setup_auth.py on the Pi.
  • Everything is LAN-only; there is no rate limiting — don't expose port 8000 to the internet without a VPN.
